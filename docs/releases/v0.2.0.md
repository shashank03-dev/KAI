First public release of Kai: an open-source desktop app that lets an open
model (Gemma 4 by default) use your computer one visible step at a time,
while you watch and can stop it instantly.

## Since 0.1.0

- One computer-tool contract for every model: OpenAI's computer-use loop
  and open models share the same versioned actions, validation and guards.
- Settings › Accounts & models: sign in with ChatGPT/Codex or Claude Code,
  refresh model catalogs, and use any compatible cloud or local endpoint.
- Safety hardening: no screenshots leave after sensitive input, exact
  actions shown in approval dialogs, `open_app` and dialog-shortcut
  bypasses closed, bounded replies and cancelled inference before acting.
- A run stops once its result is independently verified.
- macOS: Settings crash fixed, account connections rebuilt.
- App: compact layouts, scrolling and transcript fixes; new icon.

| OS | File |

| Linux x86_64 (Xorg recommended) | `kai-linux-x86_64.tar.gz` |
| Windows x86_64 | `kai-windows-x86_64.zip` (unsigned: SmartScreen › *More info › Run anyway*) |
| macOS Apple Silicon | `kai-macos-aarch64.zip` (ad hoc signed: Control-click Kai.app › Open the first time) |

Each archive has a `.sha256` next to it. Unpack and run `kai-app`; the
`kai` command-line tool is next to it (on a Mac, inside `Kai.app`).

## What's in it

- The desktop app (onboarding, live run view, settings, skills, models) and
  the `kai` CLI (`run`, `doctor`, `bench`, `models`, `skill`, `mcp`).
- Model backends: your own vLLM server, Gemini API, any OpenAI-compatible
  endpoint, and fully offline local models through the model store.
- Safety: risky actions ask first, password fields are always high risk,
  on-screen text is treated as data, CAPTCHAs and codes go to you, and three
  ways to stop (`Ctrl+Alt+Esc`, mouse to the top-left corner, Stop).
- 10 shipped skills and a 30-task benchmark (`kai bench`).

## Tested for this release

- Linux, Windows and macOS: build, the full test suite, and a smoke test of
  the packaged CLI (`skill validate`, `models list`, mock benchmark) on
  GitHub's runners.
- Linux: `kai` and `kai-app` driven end to end on a headless X11 desktop
  (26/26 recorded tasks on the real desktop; onboarding clicked through).
- Live-model numbers are in the README with how they were measured.

## Known limits

- Windows: the CLI is smoke-tested on CI; the desktop app has not been
  driven by hand on a Windows machine yet. Reports welcome.
- Linux on Wayland can capture the screen but only click and type into
  XWayland apps; use an Xorg session for full control.
- Experimental switches (executor, run memo, task checks, browser lane on
  Windows) stay off by default until a live A/B shows they help.
